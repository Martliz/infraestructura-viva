Infraestructura Viva

AWS de punta a punta, en local y con cero costo.

Un prototipo que aprovisiona seis servicios de AWS por código con un solo comando: RDS PostgreSQL, S3, DynamoDB, SNS, SQS y CloudWatch. Corre sobre Floci, un emulador de AWS de código abierto, y usa boto3 real, así que el mismo código sirve para migrar a AWS cambiando solo el endpoint y las credenciales.

El caso

Qué pedía el módulo, dónde estuvo la dificultad y cómo quedó resuelta.

La actividad

Llevar a la práctica una arquitectura diseñada en papel: base de datos relacional con consultas de negocio, almacenamiento de objetos, tabla NoSQL, mensajería asíncrona y un plan de monitoreo con alarmas. El entregable debía demostrar que la arquitectura funciona, no solo describirla.

El desafío

Validar seis servicios AWS integrados sin incurrir en costos ni depender de credenciales temporales, de forma que el mismo código sirviera después en AWS real.

La solución

Un contenedor con Floci (puerto 4566) y una API FastAPI que al iniciar aprovisiona toda la infraestructura con boto3: buckets S3, tabla DynamoDB, tema SNS suscrito a una cola SQS, instancia RDS PostgreSQL con esquema y datos de prueba, y dos alarmas de CloudWatch conectadas a SNS. El código no tiene nada específico del emulador salvo el endpoint_url.

Obstáculo resuelto

Floci no implementa un evaluador periódico de alarmas, y SetAlarmState no ejecuta las AlarmActions. Lo documenté y creé POST /cloudwatch/simular-alarma, que publica en SNS al forzar el estado ALARM. La configuración de las alarmas es idéntica a la de AWS real, donde la evaluación automática funcionaría sin cambiar código.

Aprendizajes

  • Un emulador reproduce la API, no todo el comportamiento. Hay que probar los supuestos y documentar las diferencias.
  • El código portable abarata el paso a producción. Solo cambian el endpoint y las credenciales.
  • La infraestructura por código es reproducible y verificable. Cualquiera puede levantarla y revisarla.
  • Un README claro es parte del producto.

Qué se puede probar

Cada servicio queda expuesto en la API y se prueba desde Swagger UI, en localhost:8000/docs, sin escribir código.

Ejecútalo en tu equipo

Solo necesitas Docker Desktop (o Docker con Compose) y Git.

Clona el repositorio

Descarga el proyecto y entra a la carpeta.

git clone https://github.com/Martliz/infraestructura-viva.git && cd infraestructura-viva

Levanta el entorno

El primer arranque tarda entre 30 y 60 segundos mientras Floci levanta PostgreSQL.

docker compose up --build

Abre Swagger UI

Prueba primero GET /aws/estado: si muestra RDS, buckets, tabla, cola y alarmas, todo quedó aprovisionado.

http://localhost:8000/docs
